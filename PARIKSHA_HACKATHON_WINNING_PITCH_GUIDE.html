1 The 60-Second Elevator Pitch (Use when judge says: "Tell me what you built")

Time: 55 seconds

"Good morning judges. Problem statement IM-105 is about proving real skills over inflated template resumes. Today, 78% of resumes contain exaggerated claims, and screening is heavily biased by college pedigree or keywords.

We built ProofCard (Pariksha) — an autonomous code, live-deployment, and resume forensic platform that turns raw deliverables into an immutable 100-Point ProofCard.

Unlike traditional platforms that only accept a single GitHub repo or toy algorithmic puzzles, our platform takes real GitHub repositories, offline ZIP files, deployed live websites, or full PDF resumes. It strips all demographic and college pedigree bias, runs Tree-sitter AST and Git-DNA forensics alongside an Apify web crawler to detect copied templates, and verifies genuine ownership through an oral 10-question Viva Voce Defense Engine.

The final result is a cryptographically verified, 6-axis forensic scorecard that proves whether a candidate actually wrote the code they claim. It is live in production right now at proofcard.vercel.app."

  • Evaluates candidate open-ended viva answers against multi-concept rubrics.

Tree-Sitter Multi-Language AST & Radon

Polyglot Abstract Syntax Tree Parser
Code Forensics

Where it is used: backend/services/code_analyzer.py.

Stage 3

🧠 Core Methods & Scoring Algorithms

Algorithms

The Unified 100-Point Forensic Scoring Formula

Tell judges: "We replace subjective interview ratings with a deterministic 100-mark mathematical matrix."

ProofCard Score (100) = Code_AST_Depth (35) + Git_DNA_Authorship (25) + Live_Deployment (15) + Viva_Defense (25)
1. AST & Code Depth (35)

Cyclomatic complexity (>5), modularity, error recovery pipelines, test-suite ratio.

2. Git-DNA Authorship (25)

Commit chronology curve, author email consistency, burst anomaly detector (<20% clone penalty).

3. Live Deployment (15)

HTTP 200, valid SSL, <500ms latency, Apify content originality vs tutorial templates.

4. Viva Defense (25)

10 oral defense questions evaluating architectural trade-offs, edge-case mitigation, and depth.

Tandem Evaluation Algorithm (When Candidate Has Both Repo & Live Site)

When a candidate uploads a resume like Priyanshu's that lists both a GitHub repo and live deployed websites (AlleyRich, Global Logic Media), ProofCard triggers Tandem Concurrency:

Step 1: Code AST Analysis Runs Tree-sitter on the Git repo, evaluating function complexity and commit timeline.
Step 2: Apify Web Crawler Inspects the live website, runs SSL checks, and crawls Google for template matches concurrently.
Step 3: Viva Synthesis (6 + 4) Synthesizes 6 questions from AST hot-spots + 4 questions from live deployment architecture = 10 questions.

Stream Segregation: Technical vs Non-Technical (MBA / BBA)

If an MBA, Product Manager, or Business Development candidate applies:

  • No Code Required: The code repository requirement is waived; candidate provides a portfolio, Notion deliverable, or strategic deck link.
  • Business Case Viva: The viva questions automatically pivot from syntax/AST to CAC/LTV payback periods, go-to-market trade-offs, and stakeholder conflict resolution.
  • Prevents Demographic & Pedigree Bias: Evaluates quantified business thinking instead of penalizing non-technical candidates with a broken code scanner.

🛡️ Judge Q&A Armor (Tough Questions & Winning Answers)

Defense Armor
Judge Question 1

"What if a candidate only submits a PDF resume without a GitHub link?"

Your Answer: "That's why we built our layout-aware Annotation Harvester. When a candidate uploads a PDF resume, our engine reads both rendered text and embedded interactive PDF annotations (/Annots & /URI), extracting any hidden staging links, live sites, or portfolio domains. If the candidate genuinely has no public code, our AI routes them to the Resume Viva path, generating targeted conceptual questions directly from their resume project bullet points."
Judge Question 2

"Senior engineers work on private company code under NDA. They give live project URLs, not public GitHub repos. How do you evaluate them?"

Your Answer: "Traditional code scanners break here, but ProofCard includes an Apify Live Website Evaluator. The candidate submits their live URL (e.g. alleyrich.com or Vercel app). Our engine inspects HTTP status, SSL, latency, and DOM semantics, and queries the Apify Google crawler to verify that their copy and layout aren't a template clone. We then generate oral defense questions focused on system scalability, caching, and failure recovery."
Judge Question 3

"Hiring isn't just software engineering. What about MBA, Product, or Marketing candidates?"

Your Answer: "ProofCard features an Intelligent Stream Segregation Gate. If a candidate is in an MBA, Product, or Business track, code AST requirements are waived. Instead, they submit a strategic deliverable, case study, or presentation link, and our viva engine pivots to business fundamentals: ROI attribution, CAC/LTV payback, and cross-functional stakeholder alignment."
Judge Question 4

"What if a candidate uses ChatGPT to answer your viva questions during the interview?"

Your Answer: "Two defenses make that virtually impossible: First, our oral viva questions are deeply anchored to specific functions and line numbers in their own codebase (e.g. 'On line 42 of auth.py, why did you choose synchronous bcrypt hashing inside an async endpoint?'). Generic LLMs hallucinate without knowing their full codebase context. Second, we enforce timed oral defense via Web Speech audio, requiring candidates to explain architectural trade-offs in real time."
Judge Question 5

"How does your platform prove it eliminates pedigree bias?"

Your Answer: "Our Anti-Bias Vault redacts all candidate names, gender indicators, geographic locations, and college brand names before the 100-mark scoring ledger computes a single point. A Tier-3 student with custom microservices, clean Git-DNA, and strong viva defense will mathematically outscore a Tier-1 student who merely submitted an uncredited tutorial clone."
